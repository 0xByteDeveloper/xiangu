 3. YAPISAL FARKLILIKLAR (tasarım felsefesi)
================================================================================
 3.1 BÜTÜNLÜK: vmp tek çekirdek + çok format; XProtect "motor + İKİ
     freestanding blob (VM, XRT) + UI" üç parçalı — blob'lar -fno-jump-
     tables/-fno-stack-protector ile PIC, libc'siz.
 3.2 DERLENMİŞLİK: vmp MSVC/Qt zinciri (Windows makinada); XProtect Linux'ta
     çapraz: gcc blob → ld -Ttext=0x100000 → objcopy -O binary → python
     gen_*_blob.py → C++ dizi → zig link. "VS2019'da derlenebilme" hedefi
     için not: mevcut kaynak saf Win32 + C++17 olduğundan MSVC'ye taşınması
     düşük engelli görünür; blob'lar zaten önceden üretilmiş veri olarak
     commitlenmiştir (vm_blob.cpp/xrt_blob.cpp) — MSVC tarafında da aynı
     veri dizileri bağlanabilir; gereken şey proje dosyası (.vcxproj)
     üretimidir.
 3.3 VM FELSEFESİ: vmp — handler üretimi C++ ile derleme zamanında,
     itab switch/case, 10 farklı VM, opcode cryptor zincirleri;
     XProtect — 43 opcode tek yorumlayıcı, if/else zinciri (PIC şartı),
     polimorfik itab FNV tohumlu Fisher-Yates (tablo taşınmaz),
     CFB bayt-kodu (tek-bayt tamper yayılımı) + adım bütçesi 1<<24.
 3.4 ANTI-DEBUG FELSEFESİ: vmp — geniş yüzey (20+ sinyal, kernel mod dahil);
     XProtect — istisna-dispatch'siz 2 kesin-kanıt kontrolü (K1/K2) +
     bilinçli yok-liste (oyun DRx/int3-hook/AV-VEH yanlış-pozitifleri).
 3.5 STRING MODELİ: vmp orijinali şifreleyip yazar; XProtect şifreli ÖZEL
     KOPYA .vmp0'da üretir, orijinale dokunmaz (native/M referansları
     güvende).
 3.6 SEH: vmp .pdata'yi derlemede yeniden üretir; XProtect RtlAddFunction-
     Table ile ÇALIŞMA ANINDA dinamik kayıt (JIT modeli — dd[3]'e dokunmaz).
 3.7 KANIT KÜLTÜRÜ: vmp gtest xtest seti; XProtect diferansiyel koşular
     (Unicorn orijinal↔korumalı), wine RCODE matrisi, statik çözümleyici
     (static_ad_check.py — çıktı EXE'den bytecode'u çözüp ilk op'u
     doğrular), 3-yönlü T1/T2/T3 + "sahte-başarı koruması" (rc!=0'da
     çıktı hiç yazılmaz).
